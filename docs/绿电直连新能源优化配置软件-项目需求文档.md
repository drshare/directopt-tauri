## 二、项目背景与目标

### 2.1 项目背景

随着绿电直连模式（新能源发电与负荷直接相连供电）政策的推进，项目投资决策需要科学测算风电、光伏、储能的最优容量配置。人工试算工作量大、难以兼顾多目标与多重约束，迫切需要一套自动化的优化配置计算工具。

### 2.2 项目目标

1. **自动寻优**：在给定边界条件与约束下，按用户选定目标（综合电价最低 / 绿电电价最低 / 初投资最低）自动计算风电、光伏、储能的最优容量配置；
2. **数据便捷导入**：支持通过 Excel 模板批量导入静态参数与全年 8760 小时时序数据；
3. **计算高效**：采用遗传算法替代枚举法，结合异步任务架构，在工程实践可接受的时间内（3~5 分钟）完成优化计算；
4. **结果可追溯**：生成包含输入参数汇总、核心优化结果、8760 小时逐时运行数据的 Excel 报告；
5. **政策合规**：算法与参数默认值符合发改能源〔2025〕650 号、发改价格〔2025〕1192 号文件要求，为投资决策提供科学依据。

### 2.3 目标用户

| 用户类型 | 典型角色 | 使用诉求 |
| --- | --- | --- |
| 投资决策者 | 绿电直连项目业主、投资机构 | 快速获得容量配置与电价测算结果，辅助决策 |
| 规划/设计人员 | 能源规划师、电力设计院工程师 | 多方案比选、参数敏感性分析、政策合规校验 |
| 咨询顾问 | 能源咨询机构、第三方评估机构 | 出具详细计算报告，作为项目可行性依据 |

## 三、用户角色与使用场景

### 3.1 角色定义

| 角色 | 权限范围 | 说明 |
| --- | --- | --- |
| 普通用户 | 全部业务功能（注册/登录、上传、计算、导出、文件管理） | 使用软件完成容量配置测算 |
| 系统管理员 | 平台运维、任务队列管理 | 保障计算服务可用性（后台） |

### 3.2 核心使用场景

- **场景 A：新项目测算** —— 用户注册/登录 → 下载模板 → 填写静态参数与 8760h 时序数据 → 上传（输入文件可选、曲线必选）→ 参数校验 → 计算 → 查看结果 → 导出报告。
- **场景 B：方案比选** —— 同一项目调整优化目标、输配电费方案、参数上下限等，多次计算比较结果。
- **场景 C：参数敏感性分析** —— 结果展示模块提供固定两要素、变动单一要素（风电/光伏/储能）的敏感性分析。
- **场景 D：合规校验** —— 通过自发自用占比、余电上网比例、弃电率等约束的自动校验，判断方案是否满足 1192 号文要求。
- **场景 E：历史数据管理** —— 在文件管理中查看、删除历史计算输入文件与计算结果（来源：截图 OCR）。

### 3.3 典型业务流程

```
[注册/登录] → [下载模板] → [填写模板] → [上传文件(输入可选/曲线必选)]
    → [参数确认/调整] → [参数校验] → [启动计算(排队/进度)]
    → [结果展示(最优配置/占比指标/电价指标/敏感性分析/8760h曲线)]
    → [导出Excel报告]
```

## 四、总体架构需求

### 4.1 架构形态

- 采用 **B/S 架构**，软件部署在“说能解电”云计算中心；
- 用户通过浏览器访问，无需安装客户端；
- 访问地址：`http://150.158.94.206`（注意：**不是 https 开头**，访问协议需兼容 http）。

### 4.2 系统组成

| 组成 | 职责 |
| --- | --- |
| 前端 Web 界面 | 登录注册、模板下载、文件上传、参数展示与编辑、计算控制、结果展示、文件管理 |
| 计算服务 | 参数校验、8760h 仿真、遗传算法优化求解 |
| 任务队列 | 多用户并发计算任务的排队调度（“任务等待中…”状态） |
| 文件服务 | 模板下发、上传文件存储、结果报告生成与下载、历史文件管理 |

### 4.3 平台技术架构（来源：截图 OCR——平台资讯）

- 采用 **Redis 高性能缓存** + **Celery 异步任务队列**架构；
- 耗时操作（优化计算等）**后台异步处理**，页面响应速度提升 80%+，避免加载卡顿；
- 界面/首页提供**最新资讯**展示区（版本更新、试用活动、服务升级公告）。

### 4.4 部署要求

- 支持多用户同时访问，具备任务排队机制；
- 计算任务运行期间需保持页面不关闭（关闭将导致结果无法显示），前端须有明确提示。

## 六、算法需求（AR）

### AR-1 优化目标（3 类）

软件内置 3 类优化目标，由用户在界面选择（截图确认选择控件及说明文字）：

| 目标 | 界面说明文字（截图） |
| --- | --- |
| 综合电价最低 | 考虑风光储投资和运行费用、外购网电成本后的综合电价最低 |
| 绿电电价最低 | 考虑风光储投资和运行费用后的绿电电价最低 |
| 初投资最低 | 风光储初投资最低 |

#### AR-1.1 优化目标 1——综合电价最低

- 定义：综合电价是综合考虑风光储初投资、运行成本和电网购电成本后对负荷的供电价格。

**总成本公式（全生命周期总成本现值）**：

```
TC = IC + Σ_{t=1}^{n} OC_t/(1+r)^t + OC_x/(1+r)^x        (1)
```

式中：
- `TC` —— 全生命周期总成本（现值）；
- `IC` —— 初始投资成本：`IC = C_wind × P_wind + C_pv × P_pv + C_ess × E_ess + FC`（C 为单位造价，P 为功率容量，E 为储能容量，FC 为其他固定初投资，如绿电直连输电线路投资）；
- `OC_t` —— 第 t 年运行成本：含运维成本、电网购电成本、自发自用电量输配电费、政府性基金及附加（按“两收两不收”规则计算）；对允许余电上网的项目，年运行成本中应**扣除余电上网收益**；
- `OC_x` —— 第 x 年的一次性运维成本（如更换储能电池）；
- `r` —— 折现率；
- `n` —— 项目生命周期（通常取 15~20 年）。

**总收益公式**：

```
TR = p_z × Σ_{t=1}^{n} Q_t/(1+r)^t                       (2)
```

式中：`TR` —— 全生命周期总收益（现值）；`p_z` —— 综合电价；`Q_t` —— 第 t 年负荷用电量。

**综合电价求解**：当 TR = TC 时，设定的折现率即收益率，联立式（1）（2）求得综合电价：

```
p_z = ( IC + Σ OC_t/(1+r)^t + OC_x/(1+r)^x ) / Σ Q_t/(1+r)^t      (3)
```

- TR < TC：综合电价对应的收益率低于设定折现率；
- TR > TC：综合电价对应的收益率高于设定折现率。

**求解思路**：给定项目边界条件与风光储配置，式（3）中初投资、一次性运维成本、负荷用电量可直接计算，仅运行成本需通过 **8760h 仿真**计算；故每组风光储配置对应一个综合电价，比较所有可能配置即可得到综合电价最优的配置。

#### AR-1.2 优化目标 2——绿电电价最低

- 定义：绿电电价是综合考虑风光储初投资、运行成本后对负荷供绿电的价格。
- 与综合电价区别：运行成本中**不计入网电成本**，对负荷供电量中**不计入网电电量**。

```
p_g = ( IC + Σ OC_g,t/(1+r)^t + OC_x/(1+r)^x ) / Σ Q_g,t/(1+r)^t   (4)
```

式中：`OC_g,t` —— 第 t 年运行成本（不含电网购电成本）；`Q_g,t` —— 第 t 年负荷用电量。

#### AR-1.3 优化目标 3——初投资最低

- 给定项目边界条件与风光储配置，初投资虽可直接计算，但仍需通过 **8760h 仿真**核对约束条件是否满足（自发自用占总可用发电量比例、自发自用占总用电量比例、余电上网比例等）；
- 在**所有满足约束条件**的风光储配置中，选择初投资最低的配置作为最优解。

#### AR-1.4 年电网购电成本 / 自发自用输配成本计算（来源：截图——输出数据表备注）

- **年电网购电成本**
  - 方案一：`电量电价 + 上网环节线损费 + 系统运行费 + 政府性基金及附加 + 接入公共电网容量 × 平均负荷率 × 8760 × 电度输配电价`
  - 方案二：`电量电价 + 上网环节线损费 + 系统运行费 + 政府性基金及附加 + 实际购网电量 × 电度输配电价`（输配电费按实际用电量缴纳）
- **年自发自用输配成本**
  - 方案一：`政府性基金及附加`（自发自用电量仅缴纳基金及附加，不缴输配电费）
  - 方案二：`输配电费 + 政府性基金及附加`（方案二对含自发自用电量在内的实际用电量征收输配电费）

### AR-2 约束条件（9 项）

#### AR-2.1 电量平衡约束

任意时刻供电量等于负荷所需电量：

```
P_wind(i) + P_pv(i) + P_ess,d(i) − P_ess,c(i) + P_grid,b(i) = L(i)
```

式中：
- `P_wind(i)`、`P_pv(i)` —— 周期 i 风电、光伏实际发电功率（受资源禀赋影响，通过出力曲线约束）；
- `P_ess,d(i)`、`P_ess,c(i)` —— 周期 i 储能放电/充电功率，状态由风光发电量与负荷差值决定；
- `P_grid,b(i)` —— 周期 i 电网购电功率；
- `L(i)` —— 周期 i 负荷用电功率（按负荷曲线确定）。

> 电量平衡恒等式（截图——输出数据表备注）：
> `负荷用电量 + 储能充电量 + 余电上网电量 = 新能源实际发电量 + 储能供电量 + 下网电量`

#### AR-2.2 风光出力约束

任意时刻风光实际发电功率不大于出力曲线对应的最大发电功率：

```
P_wind(i) = P_wind × f_wind(i)
P_pv(i)   = P_pv   × f_pv(i)
```

式中：`P_wind`、`P_pv` 为装机容量；`f_wind(i)`、`f_pv(i)` 为发电功率标幺值（某时刻最大发电功率 ÷ 装机容量）。

#### AR-2.3 下网电功率约束

```
P_grid,b(i) ≤ P_grid,bonn
```

式中：`P_grid,bonn` 为并网容量，即最大允许下网功率。

#### AR-2.4 储能充放电功率约束

```
0 ≤ P_ess,c(i) ≤ P_ess,rated
0 ≤ P_ess,d(i) ≤ P_ess,rated
```

#### AR-2.5 储能容量约束

```
E_ess,rated × SOC_min ≤ E_ess(i) ≤ E_ess,rated × SOC_max
```

#### AR-2.6 储能电量平衡约束

```
E_ess(i) = E_ess(i−1) + P_ess,c(i) × η_c × Δt − P_ess,d(t) × Δt / η_d
```

式中：`η_c`、`η_d` 分别为储能充电效率与放电效率。

#### AR-2.7 自发自用电量占比约束

```
(Q_wind,s + Q_pv,s) / (Q_wind,t + Q_pv,t) × 100% ≥ 60%     （1192 号文：不低于 60%）
(Q_wind,s + Q_pv,s) / L_s               × 100% ≥ 30%     （1192 号文：不低于 30%，2030 年起不低于 35%）
```

#### AR-2.8 余电上网占比约束

```
(Q_wind,grid + Q_pv,grid) / (Q_wind,t + Q_pv,t) × 100% ≤ 20%    （一般不高于 20%，详见地方规定）
```

#### AR-2.9 弃电率约束

```
( (Q_wind,t − Q_wind,s − Q_wind,grid) + (Q_pv,t − Q_pv,s − Q_pv,grid) ) / (Q_wind,t + Q_pv,t) × 100% ≤ 20%   （目前无硬性规定，可自行设定）
```

> 恒等式提示：自发自用占总可用发电量比例 + 余电上网比例 + 弃电率 = 100%。

### AR-3 优化算法（遗传算法 GA）

#### AR-3.1 采用遗传算法的原因

- 理论上可用枚举法穷举所有风光储配置求最优解，但**枚举法计算效率太低**：如择优范围为 5~500、步长 5 时，组合方案数达 100³ 个（约 100 万量级），按单方案 0.1 秒测算总耗时约 **28 小时**，无法满足工程实践的高效决策需求；
- 范围扩大或步长缩小时，枚举法陷入**维度灾难**；
- 遗传算法具备强大全局寻优能力，适合目标函数不可导、不连续或存在大量局部极值点的复杂优化问题（由 John Holland 教授 1975 年提出）。

#### AR-3.2 算法流程（截图——GA 流程图）

```
开始
  → 初始化种群：随机生成 N 个个体（编码为二进制/实数向量）
  → 计算每个个体的适应度值（基于目标函数和约束处理）
  → 是否达到终止条件？
      是 → 输出最优解及对应适应度 → 结束
      否 → 选择操作：轮盘赌 / 锦标赛 / 排序等 → 生成父代种群
         → 交叉操作：单点 / 多点 / 模拟二进制等 → 生成子代个体
         → 变异操作：位翻转 / 高斯扰动等 → 维持种群多样性
         → 组合父代与子代（或仅使用子代）→ 计算新种群中各个体适应度 → 回到终止条件判断
```

说明：截图流程与文字版 7 步一致，并补充了具体算子（选择含“排序”策略；交叉含“模拟二进制”交叉）。

#### AR-3.3 遗传算法参数（界面可配置，含默认值——来源：截图）

| 参数 | 默认值（截图） | 说明 |
| --- | --- | --- |
| 遗传代数 | 40 | 遗传算法的进化代数 |
| 交叉概率 | 0.5 | 随机选中一对个体执行交叉操作的可能性 |
| 变异概率 | 0.3 | 随机选中个体执行变异操作的可能性 |
| 种群大小 | 100 | 初始种群的个体数量 |

#### AR-3.4 8760h 仿真要求

- 以全年 8760 小时为仿真周期，逐时校验电量平衡、储能状态、各项占比约束；
- 运行成本、自发自用/余电/弃电量等指标均基于逐时仿真累加得到；
- 仿真数据精度应支持 1 小时粒度。

## 九、非功能需求（NFR）

### NFR-1 性能

| 项 | 要求 |
| --- | --- |
| 单次优化计算耗时 | 一般 3~5 分钟 |
| 并发支持 | 多用户同时提交计算任务，具备排队机制 |
| 页面响应 | 依托 Redis 缓存 + Celery 异步架构，耗时操作后台处理，页面响应速度较同步实现提升 80%+（来源：截图） |
| 数据规模 | 支持 8760 小时时序数据处理 |

### NFR-2 可用性

- B/S 架构，浏览器直接访问，无需安装客户端；
- 计算期间页面不可关闭（关闭将丢失结果展示），须有强提示；
- 提供排队状态与进度反馈，避免用户无感知等待。

### NFR-3 可靠性

- 参数校验失败不得进入计算；
- 排队/计算状态需可恢复、可重试；
- 生成报告数据完整、可追溯。

### NFR-4 安全性

- 注册/登录鉴权（云计算中心统一认证，含验证码）；
- 上传文件做格式与结构校验，防止异常文件；
- 用户数据隔离（多用户场景，个人文件管理互不可见）。

### NFR-5 兼容性

- 支持主流浏览器（Chrome/Edge/Firefox 等）；
- 模板文件格式为 xlsx（Excel 2007+）。

### NFR-6 可维护性与可扩展性

- 算法参数（遗传代数、概率、种群等）可配置化，便于调优；
- 政策参数（占比下限、上限等）可配置化，便于政策调整时快速更新；
- 模板版本管理（如 _2.1 版本号）；
- 任务架构（Redis + Celery）支持横向扩展。
