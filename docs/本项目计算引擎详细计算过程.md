# 本项目计算引擎详细计算过程

> 本文档完整描述本项目（Tauri 桌面端）从输入到输出的全部计算过程，所有公式与实现
> 一一对应源码 `src-tauri/src/compute/` 模块，并经黄金对拍测试（与标准软件输出逐位
> 对比）验证。算法原理符合《绿电直连新能源优化配置软件 V2.2 使用说明书》第一章
> "算法原理"，以及发改能源〔2025〕650 号、发改价格〔2025〕1192 号政策要求。

---

## 一、总体架构与数据流

```
前端 (Vue 3 + TypeScript)                    后端 (Rust, src-tauri)
┌─────────────────────────┐                 ┌──────────────────────────────┐
│ 上传 xlsx（base64）      │  parse_input_file│ input_parse.rs 解析参数回填   │
│ 参数表单（useParams）    │ ───────────────▶│                              │
│ 曲线解析（fileParsers）  │                 │                              │
│                         │                 │                              │
│ start_compute(params,   │ ───────────────▶│ engine.rs  run_compute()     │
│   curves)               │                 │   1. 校验 → 2. GA 寻优        │
│                         │                 │   3. 8760h 仿真 → 4. 经济性    │
│ ◀── compute://progress ─│   逐代进度事件   │   5. 敏感性 → 6. 结果汇总      │
│ ◀── 结果负载 payload  ───│                 └──────────────────────────────┘
│ 结果展示 / 报告导出       │
└─────────────────────────┘
```

- 计算全部在后端 Rust 执行（`tauri::async_runtime::spawn_blocking` 阻塞线程，
  不阻塞 UI），前端仅传参与展示。
- 每代 GA 进化通过 `compute://progress` 事件推送进度（5% → 90%，按代数线性映射）。
- 取消：前端 `cancel_compute` 置位 `AtomicBool`，GA 在每代检查点安全终止。

## 三、单方案完整评估链路（`engine.rs: evaluate_config`）

GA 种群中**每个个体** = 一组配置 (风电 kW， 光伏 kW， 储能 kWh)，
评估链路为：

**8760h 仿真 → 经济性计算 → 约束检查 → 适应度**

### 3.1 逐时仿真（`simulate.rs: SimContext::run`）

派生量（每方案一次）：

- 储能额定功率 `P_rated = E_ess × C`（kW）
- SOC 上限 `SOC_max = E_ess`；下限 `SOC_min = E_ess × (1 − DOD)`（kWh）
- 初始电量 `SOC_init = clamp(E_ess × 初始电量%, SOC_min, SOC_max)`
- 全年余电上网预算 `feed_budget = 余电上限% × 理论发电量`
  （理论发电量 `Q_total = Σᵢ (P_wind × f_wind(i) + P_pv × f_pv(i))`）

逐时调度（第一遍，i = 1…8760）：

1. **风光出力**（风光出力约束）：`wind_i = P_wind × f_wind(i)`，`pv_i = P_pv × f_pv(i)`，
   理论出力 `theory_i = wind_i + pv_i`。
2. **储能充电**（时段允许且 SOC 未满）：
   - 可充上限（交流侧）`max_ac = min((SOC_max − SOC)/η_c, P_rated)`；
   - 有盈余（theory > 负荷）：充盈余 `min(max_ac, 盈余)`；
   - 无盈余但用户勾选了充电优先时段：风光发电优先充电 `min(max_ac, theory_i)`，
     有余再供负荷。
3. **净功率** `net = theory_i − charge_ac − load_i`：
   - `net ≥ 0`：记为盈余 `surplus[i] = net`（上网/弃电第二遍统一分配）；
   - `net < 0`（缺口）：先**储能放电** `min((SOC − SOC_min) × η_d, P_rated, 缺口)`，
     不足部分**下网购电** `min(剩余缺口, 接入公共电网容量)`，仍不足计**缺供**
     （视为重约束违反）。
4. **储能电量递推**（储能电量平衡约束）：
   `SOC ← clamp(SOC + charge_ac × η_c − discharge_ac / η_d, SOC_min, SOC_max)`
   直流侧口径：充入 = 交流×η_c，放出 = 交流/η_d。

逐时累计（与上网分配无关量）：理论发电量、下网电量、储能交/直流侧充放电、负荷，
以及网电成本基数 `Σ grid_i × (电量电价 + 线损 + 系统运行费 + 基金附加)`。

第二遍——**余电上网分配**（按电价优先级，与标准软件口径一致，已对拍验证）：

- 将有盈余的小时按**电量电价从高到低**排序；
- 依次分配 `feed_i = min(盈余_i, 余电最大上网功率, 预算剩余)`；
- 预算耗尽或盈余用尽后，剩余盈余计**弃电**；
- `实际发电量_i = 理论_i − 弃电_i`；
- 余电上网收益 `Σ feed_i × 电量电价_i`；自发自用输配成本基数按实际发电量累计。

全年电量平衡恒等式（AR-2.1，测试强制验证）：

```
负荷 + 储能充电(交流) + 余电上网 = (理论发电量 − 弃电) + 储能供电(交流) + 下网 + 缺供
```

### 3.2 经济性计算（`economics.rs: compute_economics`，单位：元）

**初投资**：

```
IC = C_wind × P_wind + C_pv × P_pv + C_ess × E_ess + FC × 10⁴
```

**年运行成本各项**（单年 8760h 仿真结果外推至各年）：

- 运维 `maint = IC × 运维占比%`
- 工资 `salary = 万元/人年 × 10⁴ × 定员`
- 年电网购电成本：
  - 方案一（容量法）：`购电电量成本 + 接入容量 × 平均负荷率% × 8760 × 输配电价年均值`
  - 方案二（电量法）：`购电电量成本 + 实际下网电量 × 输配电价`
  - 其中购电电量成本 = `Σ 下网_i × (电量电价 + 线损 + 系统运行费 + 基金附加)`
- 自发自用输配成本：方案一 = `Σ 实际发电_i × 基金附加`；方案二 = `Σ 实际发电_i × (输配电价 + 基金附加)`
- 余电上网收益 = `Σ feed_i × 电量电价_i`
- 展示口径年运行成本 = 购电 + 自发自用输配 + 运维 + 工资
- 计入式(1) 的年运行成本 `OC = 展示口径 − 余电上网收益`（余电上网项目扣除收益）
- 绿电口径 `OC_green = 自发自用输配 + 运维 + 工资 − 余电上网收益`（不含网电购电）

**折现**：

```
年金系数 a = Σₜ₌₁ⁿ 1/(1+r)ᵗ          （r = 折现率%，n = 评价周期）
电池更换现值 = E_ess × 单价 × 比例% / (1+r)ˣ   （x = 更换年份）
```

**全生命周期总成本与三类电价**（对应说明书式 1/3/4）：

```
TC     = IC + OC × a + 电池更换现值
综合电价 p_z = TC / (Q_load × a)                       （Q_load = 全年负荷用电量）
绿电电价 p_g = (IC + OC_green × a + 电池更换现值) / (Q_green × a)
               其中 Q_green = 负荷 − 下网电量（绿电覆盖部分）
网电电价 p_grid = 年购电成本 / 全年下网电量
```

### 3.3 约束检查（`economics.rs: check_constraints`，全年口径）

| 约束 | 公式 | 阈值 |
|---|---|---|
| 自发自用占总可用发电量 | (理论 − 上网 − 弃电)/理论 × 100% | ≥ 下限（默认 60%） |
| 自发自用占总用电量 | (负荷 − 下网)/负荷 × 100% | ≥ 下限（默认 30%） |
| 余电上网比例 | 上网/理论 × 100% | ≤ 上限（默认 20%） |
| 弃电率 | 弃电/理论 × 100% | ≤ 上限（默认 20%） |
| 缺供 | 缺供电量 > 0 即违反 | = 0 |

（逐时类约束——电量平衡、风光出力、下网功率、储能功率与 SOC——已在仿真中物理强制满足。）

### 3.4 适应度：展示口径与寻优口径

```
base = 综合电价（objective=composite）
     | 绿电电价（green）
     | 初投资/10⁴（capex，万元）
```

**展示口径**（`fitness_visible`，用于敏感性分析表）：

```
fitness_visible = base                （满足全部约束）
                = 0.98                （存在约束违反，固定哨兵值）
```

依据：V3.0 实测敏感性分析表——不满足约束的方案适应度恒为 0.98（如风电 +15%/+20%/+25%
三行因弃电率超标，适应度均为 0.98），与可行方案的 0.23x 量级形成明显区分。

**寻优口径**（`fitness_search`，仅优化器内部使用）：

```
fitness_search = base                                   （满足全部约束）
               = base + (1 + violation) × scale         （存在约束违反）
scale = base（capex 目标，量级数万元）｜ 1.0（价格类目标）
violation = Σ 各项约束超出比例 + 缺供电量/负荷
```

两者分离的原因：若不可行解统一取 0.98 常数，优化器在不可行区内失去搜索方向；
且初投资目标量级可达数万元，0.98 反而小于可行解，会导致不可行解被误判为更优。

## 四、寻优算法（`bo.rs` 贝叶斯优化 / `ga.rs` 遗传算法，可切换）

界面「寻优算法」可选两套，**默认贝叶斯优化**（V3.0 口径）。

### 4.1 算法选择与参数来源

| 算法 | 参数 | 来源 |
|---|---|---|
| 贝叶斯优化（`bo.rs`，默认） | 总评估次数 n_iter=100、初始随机采样点数 n_init=20 | V3.0 界面「算法参数」区；输入模板「总评估次数」「初始随机采样点数」 |
| 遗传算法（`ga.rs`） | 遗传代数 40、交叉概率 0.5、变异概率 0.3、种群大小 100 | V2.2 说明书 AR-3.3 |

> **口径修正**：V2.2 说明书描述的是遗传算法，但 V3.0 界面已无遗传代数/交叉/变异/种群
> 四项参数，只剩「总评估次数」「初始随机采样点数」，软件自标注为「贝叶斯优化，测试中……」。
> 因此这两项是**贝叶斯优化参数**，不是 GA 的代数与种群大小（旧版根因分析报告此处判断有误）。

### 4.2 贝叶斯优化（`bo.rs`，V3.0 口径，默认）

决策变量 3 维（风电 kW / 光伏 kW / 储能 kWh），归一化到 [0,1]³。

| 环节 | 实现 |
|---|---|
| 初始设计 | 拉丁超立方采样（LHS），`n_init` 个点（默认 20），固定种子 |
| 代理模型（目标） | 高斯过程回归：常值趋势（普通克里金，μ̂ 由 GLS 闭式估计）+ Matern 5/2 核，ARD 逐维长度尺度 + 观测噪声；超参按对数边际似然在网格上择优（先共享尺度粗搜，再逐维坐标下降） |
| 代理模型（约束） | 第二个 GP 拟合**约束违反量**（各项比例超出量之和 + 缺供比例） |
| 采集函数 | **约束 gp_hedge**：`gp_hedge(EI / LCB / PI) × P(可行)`，其中 `P(可行) = Φ(−μ_v/σ_v)`；尚未找到可行解时切换为最小化违反量（最大化 −LCB(违反量)） |
| 末段收敛 | 预算后 25% 固定切到纯开发（取后验均值最小处），不再探索 |
| 采集函数寻优 | 3072 点 LHS 候选 + 围绕当前最优的多尺度局部扰动，再 96 步收缩随机搜索精化 |
| 随机种子 | **固定种子** `0x2026_0830_0001` → 相同参数必然得到相同结果（可复现、可对拍） |
| 终止 | 评估满 `n_iter` 次（默认 100）；每步检查取消标志 |

评估次数 = `n_iter` = **100 次**完整 8760h 仿真（含 `n_init` 次初始采样）。

**为何必须分离建模约束**：择优范围取 1~500 时可行域仅约 **19%**（0~200 时为 81%），
20 个初始点里只有约 4 个可行。若把「目标 + 罚项」压成单一标量拟合 GP，代理模型学到的
主要是罚值悬崖，采集函数会持续被引向不可行区。实测该场景下单一标量 GP 的结果为
0.243553 元/kWh，改为约束 GP 后为 **0.234989 元/kWh**（改善 3.5%，并优于 V3.0 的 0.235336）。

### 4.3 遗传算法（`ga.rs`，V2.2 口径）

| 环节 | 实现 |
|---|---|
| 编码 | 实数向量 [风电 kW， 光伏 kW， 储能 kWh]，边界=择优范围×1000 |
| 初始化 | 择优范围内均匀随机生成 N=100 个个体 |
| 选择 | 锦标赛 k=3（随机取 3 个取适应度最优） |
| 交叉 | 模拟二进制交叉 SBX，η=15，按交叉概率 0.5 执行 |
| 变异 | 高斯扰动，σ = 0.1×(上界−下界)，逐基因按变异概率 0.3 触发，越界钳制 |
| 精英保留 | 每代 2 个最优个体直接进入下一代 |
| 并行 | 每个体评估（8760h 仿真）经 rayon 并行 |
| 随机种子 | **固定种子** `0x2026_0829_0001` → 相同参数必然得到相同结果（可复现、可对拍） |
| 终止 | 固定 40 代；每代检查取消标志 |

评估次数 = 种群 × (代数 + 1) ≈ 100 × 41 = 4100 次完整 8760h 仿真。

### 4.4 收尾

寻优完成后对最优配置再做一次带逐时序列的完整仿真，生成结果负载
（`engine.rs: build_payload`，寻优路径与黄金对拍路径共用，口径完全一致）。

## 五、结果汇总口径（`engine.rs`）

- **头部指标（15 项）**：最优配置 4 项（储能功率 = 容量 × 倍率）；初投资；年运行成本
  （展示口径）；下网电量占比 = 下网/负荷；自发自用占总用电量；弃电率；余电上网比例；
  自发自用占总可用电量；周期内总成本 TC；综合/绿电/网电电价。
- **投资构成（5 项）**：风/光/储系统投资 = 单位投资 × 装机；其他固定投资；初投资（应等于四项之和，测试验证）。
- **年运行成本构成（7 项）**：购电、自发自用输配、运维、工资、余电上网收益、电池更换现值、年运行成本。
- **全年电量指标（14 项）**：风光最大发电量、理论/实际发电量、弃电、储能交/直流侧充放电、
  下网、负荷、下网占比、绿电比 = 100% − 下网占比、储能年末剩余电量。
- **逐时电量平衡（8760 × 13 列）**：列口径与标准模板 output Sheet D~P 列一致。
- **敏感性分析**：固定两要素、变动单一要素，比例 ∈ {±25%, ±20%, …, ±5%, 0}（11 档），
  每档按择优范围钳制后走完整评估链路，记录适应度与约束满足情况。

## 六、与标准软件的一致性验证

### 6.1 黄金对拍测试（V2.2 口径基准）

基准：真实"新能源优化3.0"软件对同一输入（曲线模板 + 输入模板默认参数）的完整输出，
固化为三个夹具（`golden_fixture.json` / `golden_hourly.json` / `golden_expected.json`）。

7 项对拍测试（`golden.rs`，全部通过）：

1. 输入夹具与真实曲线模板关键位对拍；

## 七、与标准软件结果差异的结论

在**相同配置**下本项目引擎与标准软件逐位一致（见上节）。默认参数下一次性运行
（GA 100×40 代、择优范围 0~200/0~200/0~300）所得最优解为：

| 项目 | 标准软件报告值 | 本项目计算值 |
|---|---:|---:|
| 风电 / 光伏 / 储能 | 192.73 / 78.37 / 45.48 MW·MWh | 208.49 / 78.09 / 68.41 MW·MWh |
| 综合电价（目标值） | 0.235336 元/kWh | **0.234989 元/kWh（更优）** |

差异原因：两者同为 100 次评估预算下的启发式搜索，最优点不必相同。需要说明的是，
V3.0 的报告最优点本身也不是其搜索过程中出现过的最好点——同一张敏感性分析表里
风电 +5% / +10% 两行的适应度为 0.234807 / 0.234702，均优于 0% 行的 0.235336，
说明其自身存在局部收敛。本项目解满足说明书全部 9 项约束，目标值严格更优，
属预期行为而非计算误差。

完整对比数据见 `docs/V3.0-输出对比报告.md`。
